# 测试说明与用例

## 1. 测试范围与策略

对照设计文档 8.2 验收对应表（AT01~AT12），本项目做了三层验证：

| 层次 | 方式 | 覆盖内容 |
| --- | --- | --- |
| 接口层 | `backend/scripts/smoke_test.py`（Python 标准库，直连 REST 接口） | 正常流程 + 越权 + 非法状态 + 重复提交 + 幂等 + 文件限制 + 统计口径，共 **116 项** |
| 界面层 | 浏览器自动化（Chrome headless，Playwright） | 登录、菜单、设备增改与二维码、受理派工、工单详情、统计、账号、报修提交、开工、完工、验收，共 **21 项**，并检查控制台报错 |
| 小程序 | 静态审查 + 接口契约实测 | 页面文件完整性、JS 语法、JSON 合法性、字段与真实接口一致；渲染与真机扫码未验证（见第 6 节） |

## 2. 测试环境

- 后端：Spring Boot 3.3.5 / JDK 17.0.20，`http://localhost:8080`
- 数据库：MySQL 8.4，库 `sems`，演示数据基线为 20 台设备、6 个账号、4 张历史工单
- 浏览器：Chrome（headless，1440×900）
- 测试数据：脚本通过接口实时创建（账号以时间戳后缀区分），不依赖固定 ID 才能通过的状态

## 6. 未覆盖与已知限制

1. **小程序渲染与真机行为未验证**：本机无微信开发者工具，`wx.scanCode`、相机授权拒绝、真机上传等只做了代码层处理与接口契约核对；页面文件、JS 语法、JSON 合法性、字段名均已静态检查。
2. **性能指标未做压力测试**：文档 NFR01 的 3 秒/2 秒指标在本机单机演示中满足，但未组织 5 个并发用户的正式测试。
3. **备份恢复演练**：脚本与步骤已提供（`docs/DEPLOY.md` 第 6 节），建议演示前实际执行一次并记录数量核对结果。
4. **并发竞争**：状态流转使用「当前状态为条件」的更新语句防重复，但未使用专门的并发压测工具验证高并发下的表现。
5. 图片清理任务按小时执行，若刚上传未提交的照片需要立即清理，需等待或手动删除。
