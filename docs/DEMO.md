# 答辩演示脚本

## 0. 演示前准备（约 3 分钟）

```bash
# 1) 重置演示库（清空测试数据）
mysql -u root -p < backend/scripts/reset-demo.sql
Remove-Item -Recurse -Force backend/data/uploads -ErrorAction SilentlyContinue

# 2) 启动后端（同时托管 Web 后台）
cd backend
java -jar target/sems.jar

# 3) 打开 Web 后台
start http://localhost:8080/
```

- 微信开发者工具导入 `miniprogram/`，勾选“不校验合法域名”，编译；
- 若扫码时提示 `INVALID_LOGIN,access_token expired`，那是微信开发者工具的登录态问题：重新登录/重启工具即可；
  演示也可用**开发者工具「模拟扫码」**选择 Web 后台下载的二维码图片，或直接用页面下方**手动输入设备编号**（如 `SB-001`）；
- 若用真机演示，把 `miniprogram/utils/config.js` 的 `baseUrl` 改为电脑局域网 IP，手机与电脑同一网络；
- 演示账号：`admin/admin123`、`tech1/tech123`、`tech2/tech123`、`rep1/rep12345`、`rep2/rep12345`。

重置后的基线数据：20 台设备、6 个账号；1 张待受理报修（BX20260003，空压机）、1 张处理中维修工单（GD20260002，王磊）、2 张已完成工单（含验收记录与处理记录）。

## 1. Web 管理员：首页与设备台账（约 2 分钟）

| 操作 | 预期 |
| --- | --- |
| 用 admin 登录 | 进入首页，显示设备总数 20、待受理报修 1、待验收 0 |
| 设备台账 → 搜索 `SB-001` | 显示数控车床等设备信息 |
| 点某设备「履历」 | 抽屉展示该设备的报修记录与维修/保养工单 |
| 设备二维码页签 → 勾选 3 台 → 生成所选设备二维码 | 出现二维码预览卡片，可「下载」「批量打印」 |
| 新增设备（编号 `SB-021`） | 保存成功并出现在列表；再次用同编号新增提示“设备编号已存在” |
| 编辑设备并尝试改编号 | 提示“设备编号一经创建不可修改” |

要点：QR 内容为 `EQ:设备编号`，设备信息变更无需重新生成二维码。

## 2. 小程序报修人：扫码报修（约 3 分钟）

| 操作 | 预期 |
| --- | --- |
| rep1 登录小程序 | 首页显示「我的待受理」与入口「扫码报修」「我的报修」 |
| 扫码（或手动输入 `SB-002`） | 显示设备名称、位置与“可以填写故障报修” |
| 填写故障描述、故障类型、紧急程度，拍摄/选择 1~2 张现场照片 | 照片上传显示进度，可单张删除重传 |
| 提交 | 提示报修编号，跳转我的报修，状态「待受理」 |
| 再次点击提交（同一提交标识） | 返回原报修单，不重复创建（幂等） |
| 查看详情 | 可见设备、描述、现场照片、状态；**不显示费用** |
| 尝试扫其他部门设备（`SB-008`） | 仅展示位置与状态，禁止提交报修 |

## 3. Web 管理员：受理派工（约 2 分钟）

| 操作 | 预期 |
| --- | --- |
| 报修管理列表 | 新报修来源显示「小程序」，照片数量与提交时间正确 |
| 打开报修详情 | 展示故障现场照片（点击可看原图，显示上传人与时间） |
| 受理 → 选择负责人「李强」、计划日期当天 | 提示工单编号，报修状态变「已受理」 |
| 再次点受理（若页面未刷新） | 提示“该报修不是待受理状态”，不产生第二张工单 |
| 另一条报修点「驳回」但不填原因 | 提示“驳回原因不能为空”；填写原因后状态变「已驳回」并展示原因 |

## 4. 小程序维修人员：开工与完工（约 3 分钟）

| 操作 | 预期 |
| --- | --- |
| tech1 登录 | 首页显示待处理/处理中/待验收数量 |
| 我的工单 → 打开刚派工的工单 | 显示设备位置、故障描述、现场照片 |
| 扫码核对设备（扫 `SB-002`） | 提示“设备核对一致”；扫其他设备提示不一致且不能提交 |
| 开始维修 | 状态转「处理中」，记录开工时间 |
| 不填处理结果直接提交 | 提示处理结果不能为空 |
| 不上传完工照片提交 | 提示至少 1 张维修完成照片（BR09） |
| 填写原因/过程/结果、费用 `120.5`，上传 1~2 张完工照片后提交 | 状态转「待验收」，费用显示 120.5 |

## 5. Web 管理员：退回整改与再次验收（约 2 分钟）

| 操作 | 预期 |
| --- | --- |
| 待验收列表 → 打开该工单 | 同时展示故障现场照片与维修完成照片，可对照；显示处理记录与总费用 |
| 退回整改，不填原因 | 提示必填 |
| 填写“压力表读数偏低，请复查”后退回 | 工单回到「处理中」，验收记录保留 |
| （回到小程序 tech1）看到退回意见 → 追加整改记录 + 重新上传照片 + 提交 | 追加第 2 条处理记录，费用更新为新的总额 |
| Web 待验收 → 验收通过 | 工单「已完成」，关联报修单同步「已完成」，设备履历可查 |

## 6. 保养流程（约 2 分钟）

| 操作 | 预期 |
| --- | --- |
| 工单管理 → 安排保养：选设备、日期（明天）、负责人王磊、填写保养内容 | 生成保养工单（待处理，无关联报修） |
| 小程序 tech2 → 我的工单 → 开工 → 填写完成内容 → 上传照片 → 提交 | 状态转「待验收」 |
| Web 待验收 → 通过 | 保养工单「已完成」，计入「已完成保养」统计 |

## 7. 统计与权限（约 2 分钟）

| 操作 | 预期 |
| --- | --- |
| 查询统计，选择今天 | 设备总数、未完成工单、已完成维修/保养数、维修费用与操作一致（保养费用不计入维修费用） |
| 账号管理 → 停用「孙浩」 | 若其有未完成工单则提示不能停用；无则成功且该用户立即掉线 |
| 账号管理 → 停用最后一个管理员 | 提示“系统必须保留至少一个启用的管理员” |
| 账号管理 → 重置 tech1 密码为新密码 | 该用户既有会话立即失效；重新登录后顶部提示“密码已被管理员重置” |
| 用 rep1 访问账号管理（或直接调 `/users`） | 返回 40301，角色无权执行 |

## 8. 备用说明

- 若时间紧张，可只演示：扫码报修 → 受理派工 → 开工 → 提交完工 → 退回 → 整改 → 验收通过 → 统计变化（核心闭环，约 8 分钟）；
- 演示前务必重置数据库，避免历史测试数据干扰“待受理/待验收”数量；
- 后端重启会清空会话，演示中若重启需重新登录；
- 图片在 `backend/data/uploads`，备份演示数据时一并复制该目录。
